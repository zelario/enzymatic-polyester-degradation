# Data Sources and Computational Tools

## Current local dataset

The versioned snapshot `data/raw/pazy_proteins.json` contains 505 PAZy records.
Of these, 485 contain non-empty amino acid sequences; all 485 normalized sequences
are distinct and use the 20 canonical amino acid symbols. This does not establish
that every sequence is full length. The other 20 records lack sequences and are
excluded by the loader; no reason for their missing sequences has been established.

Each record can contain an enzyme name, sequence, organism, UniProt accession and
reported substrates. The loader normalizes sequences and produces an in-memory
DataFrame. The notebook's data ingestion cell exports `data/processed/pazy_clean.csv`
with one enzyme per row and the complete sequence in the last column. It also
shows a compact preview without the long sequences. The CSV contains the selected
analysis columns; the original JSON preserves additional nested source information.
The generated CSV is versioned for team access and can be regenerated by rerunning
the cell. Regenerate it whenever the loader or source snapshot changes.

### CSV column guide

Each row represents one enzyme entry with a non-empty amino acid sequence.

| Column | Meaning | Example |
| --- | --- | --- |
| `protein_id` | Entry identifier within PAZy; not a biological measurement | `1` |
| `protein_name` | Reported enzyme name | `IsPETase` |
| `sequence_length` | Number of amino acids in the normalized sequence | `290` |
| `uniprot_accession` | Identifier used to find the protein in UniProt; may be missing | `A0A0K8P6T7` |
| `organism_name` | Scientific name of the source organism | `Pseudideonella sakaiensis` |
| `reported_substrates` | Materials listed as substrates in the source entry; several may be listed | `Polyethylene furanoate, Polyethylene terephthalate` |
| `reported_on_pet` | PET activity annotation: 1 = reported; 0 = not reported | `1` |
| `reported_on_pur` | PUR activity annotation: 1 = reported; 0 = not reported | `0` |
| `reported_on_pla` | PLA activity annotation: 1 = reported; 0 = not reported | `0` |
| `sequence` | Complete normalized amino acid sequence, using one-letter amino acid codes | Begins `MNFPRASRLM...` |

The substrate flags are derived from the source annotations for convenient analysis.
They do not measure degradation speed, efficiency or experimental conditions.
An enzyme can have multiple flags set to 1. An empty cell represents missing
information; a zero flag does not establish experimental inactivity.

| Reported substrate | Entries with sequences |

These counts use exact substrate abbreviations and can overlap. The old PET count
of 328 incorrectly included PBAT-only entries because both polymer names contain
“terephthalate”. Do not use substring matching to assign polymer labels.

Source API: https://api.pazy.eu/api/proteins/json/
The loader uses the local snapshot when present. A future refresh must document
its retrieval date and provenance and rerun the quality checks; counts here refer
only to the committed snapshot.

## Label interpretation

`reported_on_pet`, `reported_on_pur` and `reported_on_pla` indicate whether activity
on the named substrate is reported in the snapshot. A zero means **not reported**,
not experimentally inactive. The current exploratory benchmark predicts PET
annotation status, not verified degradation activity versus inactivity.

Activity reported on another polymer is not evidence of inactivity on PET.
PHA and PHB are also polyesters and must not be described as non-polyester negative
controls. Unannotated homologues are not automatically experimental negatives.
A future activity benchmark needs explicit negative assay evidence, including the
tested substrate and experimental conditions.

## Other sources: planned, not integrated

| Source | Intended use | Local status |
| --- | --- | --- |
| PlasticDB — https://plasticdb.org | Additional reported enzymes and assay evidence | No snapshot, parser or validated counts in this repository |
| PMBD | Literature cross-checks and additional assay evidence | Not integrated |
| UniProt | Sequence retrieval and family/domain annotations | Accessions are present in PAZy; no retrieval pipeline implemented |

Previous PlasticDB record counts and PAZy overlap counts were removed because no
local data or reproducible analysis supports them. Protein domains and catalytic
residues alone do not establish plastic degradation or its absence.

## Implemented analysis

* `src/data.py`: local snapshot loading, exact substrate matching and quality checks.
* `src/features.py`: 20 amino acid frequencies and sequence length.
* `src/models.py`: dummy, logistic regression and random forest benchmarks with
  stratified five-fold cross-validation. Logistic regression scaling is fitted
  separately within each training fold.
* `src/visualizations.py`: sequence lengths and overlapping reported-substrate counts.
* `notebooks/01_data_exploration_and_baseline.ipynb`: executable analysis narrative.

Random folds may share homologous sequences, so these scores do not establish
performance on unseen enzyme families.

## Later phases: not implemented

MMseqs2 is a sequence clustering tool, not a dataset. Future cluster-based
partitions must keep each cluster on one side of the evaluation and report the
identity and coverage settings. Sequence clusters are operational similarity
groups, not automatically validated biological families.

RDKit polymer descriptors, optional protein/polymer embeddings and held-out
chemistry evaluations remain planned. Polymer structures and representation
choices must be validated before use; no validated chemical descriptor dataset
is currently included. In particular, PUR denotes varied formulations and should
not be represented by one universal structure without justification.
